# גולים — צד לקוח (חלק ב׳)

אתר סטטי ב-HTML, CSS ו-JavaScript בלבד, בלי ספריות ובלי שלב בנייה.
אין עדיין שרת: הנתונים הם נתוני דמה, ומה שהמשתמש שומר נשמר ב-`localStorage` של הדפדפן.

## הפעלה

**אפשרות 1 — שרת מקומי (מומלץ):** מתוך התיקייה `client`:

```bash
python3 -m http.server 8000
```

ואז לפתוח בדפדפן את http://localhost:8000

**אפשרות 2 — VS Code:** קליק ימני על `index.html` ← Open with Live Server.

**אפשרות 3 — בלי שרת:** לחיצה כפולה על `index.html` (נבדק בכרום).

הגופנים והדגלים נטענים מהאינטרנט. בלי חיבור האתר עובד, עם גופן ברירת מחדל ועיגול אפור במקום דגל.

## איך מנסים

1. **כניסה:** אימייל כלשהו. אין שליחת מייל בדמו, אז הקוד מוצג על המסך. אפשר גם "המשך עם Google" (חשבון דמו קבוע).
2. **חשבון חדש** מקבל ניחושי עבר ושתי ליגות, כדי שיהיו נקודות וטבלאות להציג.
3. **זמני המשחקים יחסיים לשעה הנוכחית**, כך שתמיד יש משחקים שהסתיימו, משחק חי ומשחקים פתוחים לניחוש.
4. **קודי הצטרפות לניסיון:** `BGUWEB`, `M4RK8T`. הקוד `K7P2QX` הוא של ליגה שכבר חברים בה.
5. **כלי בדיקה** בתחתית עמוד הפרופיל:
   - "משחק שנסגר בעוד דקה" — לבדיקת נעילה בשריקת הפתיחה בזמן שהעמוד פתוח.
   - "איפוס כל נתוני הדמו" — מחיקת כל הנתונים מהדפדפן.

## מבנה

```
client/
├── index.html          כניסה והשלמת שם
├── matches.html        משחקים (עמוד הבית)
├── predict.html        ניחוש — השירות המרכזי
├── leagues.html        ליגות: פתיחה והצטרפות
├── leaderboard.html    טבלה
├── profile.html        פרופיל, חוקי ניקוד וכלי בדיקה
├── css/
│   ├── base.css        משתני העיצוב (צבעים, גופנים), איפוס, מצב כהה
│   ├── layout.css      כותרת, ניווט, אזור תחתון, התאמה לטלפון ולמחשב
│   ├── components.css  כפתורים, טפסים, שבבים, תגים, הודעות
│   └── pages.css       עיצוב ייחודי לכל עמוד
├── js/
│   ├── data.js         נתוני דמה (נבחרות, משחקים, משתמשים, ליגות)
│   ├── scoring.js      חוקי המשחק: ניקוד, ★×2, נעילה בשריקת הפתיחה
│   ├── validation.js   בדיקות תקינות לכל סוגי הקלט
│   ├── api.js          הדמיית השרת — הקובץ היחיד שיוחלף בחלק ג׳
│   ├── ui.js           פונקציות עזר משותפות לממשק
│   └── pages/          קובץ אחד לכל עמוד
└── img/logo.png
```

סדר הטעינה בכל עמוד: `data` ← `scoring` ← `validation` ← `api` ← `ui` ← קובץ העמוד.
העמודים ניגשים לנתונים רק דרך `Api`, כך שבחלק ג׳ מחליפים את `api.js` בקריאות `fetch` לשרת ושאר הקוד לא משתנה.

## איפה כל דרישה

| דרישה | איפה |
|---|---|
| 1 · מבנה HTML | 6 עמודים; `header`, `nav`, `main`, `section`, `footer`; ניווט משותף בכל העמודים |
| 2 · עיצוב CSS | 4 קובצי CSS חיצוניים; Mobile-first: סרגל ניווט תחתון בטלפון, עליון מ-900px; מצב כהה לפי המערכת |
| 3 · אינטראקטיביות | סינון משחקים לפי לשונית, יום ו"רק שלא ניחשתי" (`matches.js`); בוררי +/−, ספירה לאחור ונעילה (`predict.js`); החלפת ליגה ותקופה וחיפוש (`leaderboard.js`); פתיחת ליגה והצטרפות (`leagues.js`); עריכת שם (`profile.js`) |
| 4 · השירות המרכזי | טופס הניחוש: `predict.html` + `predict.js`; הוולידציות ב-`validation.js`; השרת המדומה בודק שוב ב-`api.js` |
| 7 · ארגון הקוד | קובץ לכל אחריות; פונקציות קצרות; הערות בעברית |
